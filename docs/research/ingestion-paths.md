# Ingestion paths into New Relic: documented rules vs our converter assumptions

Written 2026-11-16. Public sources only, read as data, nothing executed, no live system touched.
Source clone: /tmp/community/nr-ingest/docs (newrelic/docs-website, sparse), /tmp/community/nr-ingest/nri (nri-prometheus,

## Contradictions ranked by items affected (our corpus sizes)

1. Grafana (about 10,000): Prometheus histogram over OTLP/Alloy-OTLP is a distribution under the base name, so every `_bucket` / `_count` / `_sum` histogram conversion returns nothing on that path (2c). Counter share of the Grafana corpus not measured here; histogram_quantile and rate(_count/_sum) are common.
2. Datadog (1,400): count and rate metrics through the OTel route are non-monotonic delta sums, documented as unsupported (6). Affects any monitor using `as_count`, `sum` on count-type, or `rate`-type metrics. No route is documented to keep names.
3. Grafana: `_sum` is a `summary`, converted as a counter with `rate(sum())` (1c). Delta vs cumulative unknown.
4. Grafana: `le` attribute is documented as `histogram.bucket.le` (1d). Data check false negative; filter on `le` fails.
5. GCP (990): service-account and user-account setups do not share the WIF names or coverage (5a). Only WIF verified. Also `cpu.utilization` still missing live.
6. AWS (340): `.byX` docs stale vs live (3b); percentile `.pNN` AWS name documented only.
7. Azure (1,050): no contradiction, but zero live evidence for any name.

## Which vendors are most at risk of returning nothing

1. Azure: every item depends on names never seen in data (docs match, no live proof).
2. Datadog: no documented route keeps names; count and rate types likely rejected on the OTel route; gauges ok.
3. Grafana: safe on remote write for counters and gauges; histograms and summaries fail on OTLP; `_sum` and `le` need L1.
4. GCP: safe on WIF for tested services; VM CPU utilization missing; other setups differ.
5. AWS: lowest risk; 13 services LIVE; untested suffixes (`.byX`) for other services remain.

## Not verified / limits of this pass

- No live query of any kind. All verdicts are "documented" or "not documented".
- docs-website pages can lag the backend (3b is an example). Page freshness fields read "never" for several pages.
- Dynatrace, GCP Ops Agent and Datadog Gateway naming: no public page found; absence of evidence only.
- Server-side behaviour (delta calculation for `_sum`, handling of colons and dots in Prometheus names, units) is not in any public repo read.
- nrdot collector: only the intro pages were read, not its config repository.
- Fluent Bit plugin page was grepped for level/severity and had no matching rule.
