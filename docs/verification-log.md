## AWS to New Relic ingestion (Metric Streams), generated by `importer ingest-setup`
- The generated Terraform (12 resources: S3 backup bucket, Firehose, metric stream, IAM roles, New
  Relic account link) applied cleanly on the first attempt and was destroyed cleanly.
- Metric names follow `aws.<service>.<MetricName>` (confirmed for DynamoDB), for example
  `aws.dynamodb.ConsumedWriteCapacityUnits`.
- Dimensions are attributes named `aws.<service>.<DimensionName>` (confirmed:
  `aws.dynamodb.TableName`). The metric value is stored in an attribute with the same name as the
  metric, so `sum(aws.dynamodb.ConsumedWriteCapacityUnits)` works.
- Other attributes present: `aws.Arn`, `aws.Namespace`, `aws.accountId`, `aws.region`,
  `aws.MetricStreamArn`, `entity.guid`, `entity.name`, `entity.type`.
- A converter-generated query, `SELECT sum(aws.dynamodb.ConsumedWriteCapacityUnits) FROM Metric
  WHERE aws.dynamodb.TableName = '<table>'`, returned 12.0 for 12 writes sent to a test table.
- Data took roughly 2-3 minutes to appear after deployment.
- The account link needs `metric_collection_mode = "PUSH"`. The test AWS account already had an
  older API-polling (PULL) link and a separate metric stream that delivered to New Relic but
  produced no data in the sandbox beforehand; this is consistent with (but does not prove) stream
  data being dropped without a PUSH link.
- New Relic's AWS account id used in the trust policy (754728514883) and the external-id scheme
  were accepted by New Relic.

## Metric data arrived; naming corrected; side-by-side vs CloudWatch (2026-10-03)
Ingestion (`ingest-setup`, prefix `conquest-live-ingest`, 12 resources) deployed; data appeared ~6
minutes after deployment.
- FOUND BY THE LIVE TEST: per-function Lambda metrics are named `aws.lambda.<Metric>.byFunction`
  (dimension attribute `aws.lambda.FunctionName` unchanged). The plain `aws.lambda.<Metric>` is the
  account-wide metric, so the first converted queries returned 0/None silently. Fixed via
  `cloudwatch_suffixes.json` (only confirmed dimension sets). Other names exist (`.byFunctionAlias`,
  `.byRegion`, DynamoDB `SuccessfulRequestLatency.put`); their dimension sets are NOT confirmed.
- Custom metrics stream as `aws.custom.<namespace after "Custom/", lower-cased>.<Metric>` with
  dimensions `aws.custom.<name>.<Dim>`. Confirmed for `Custom/ConquestLive` only; other shapes
  (hyphens, several segments, namespaces not starting with `Custom/`) are left unmapped.
- Each metric value is stored as a summary object (count, sum, min, max); `sum(metric)` sums `sum`.
- Side by side, same window, metric-stream rows attached to an entity vs CloudWatch
  `get-metric-statistics`: Lambda errors 1=1, invocations 6=6, DynamoDB writes 5=5, custom orders
  15=15. The four converted condition queries all returned real values.
- ENVIRONMENT EFFECTS that inflate raw totals (not converter bugs):
  1. New Relic's older API-polling AWS integration (collector `cloud-integrations`) delivered the
     same Lambda metrics a second time (6 extra). Filter with
     `collector.name = 'cloudwatch-metric-streams'` or disable one integration.
  2. DynamoDB had a second set of rows with no `entity.guid` (5 extra). Cause unknown; filtering to
     rows with an entity matches CloudWatch.
  Conditions and dashboards that use the plain generated queries would therefore over-count in an
  account that has both integrations. Not yet handled by the converter.
- 2026-10-05: the 4 conditions created with the old names were deleted (each re-read and matched by
  id, name and policy first) and 5 were recreated from the fixed converter (the custom-namespace
  alarm now converts). The dashboard was updated in place with `terraform apply` (1 changed, 0
  destroyed). Read back from New Relic and ran the stored queries over the 2026-10-03 data window:
  12.0 writes, 2.0 errors, 14.29% error rate, 78.8 ms average duration, 17.0 custom orders; all
  conditions disabled. Note: the condition search by name (`queryLike`) missed the newest
  condition right after creation; verify by `policyId` instead.
