# Verification log

Facts confirmed against real systems (not synthetic fixtures). Dates are 2026-10-02.

## New Relic sandbox: alert conditions (NerdGraph and Terraform)
- Created 21 (Datadog-derived) and 15 (CloudWatch-derived) disabled conditions, read them back,
  re-ran (no duplicates), ran `terraform plan` again (no drift), then removed them.
- Found and fixed: New Relic strips control characters from condition names (caused a duplicate on
  re-run); provider v3.100.1 rejects `value_function` on `newrelic_nrql_alert_condition`.

## AWS: real `describe-alarms` export
- 9 test alarms created and exported with the AWS CLI; the importer parsed the output unchanged
  (fixture: `tests/fixtures/cloudwatch-real/`). Alarms deleted afterwards.

## AWS to New Relic ingestion (Metric Streams), generated by `importer ingest-setup`
- The generated Terraform (12 resources: S3 backup bucket, Firehose, metric stream, IAM roles, New
  Relic account link) applied cleanly on the first attempt and was destroyed cleanly.
- Metric names follow `aws.<service>.<MetricName>` (confirmed for DynamoDB), for example
  `aws.dynamodb.ConsumedWriteCapacityUnits`.
- Dimensions are attributes named `aws.<service>.<DimensionName>` (confirmed:
  `aws.dynamodb.TableName`). The metric value is stored in an attribute with the same name as the
  metric, so `sum(aws.dynamodb.ConsumedWriteCapacityUnits)` works.
- Other attributes present: `aws.Arn`, `aws.Namespace`, `aws.accountId`, `aws.region`,
  `aws.MetricStreamArn`, `entity.guid`, `entity.name`, `entity.type`.
- A converter-generated query, `SELECT sum(aws.dynamodb.ConsumedWriteCapacityUnits) FROM Metric
  WHERE aws.dynamodb.TableName = '<table>'`, returned 12.0 for 12 writes sent to a test table.
- Data took roughly 2-3 minutes to appear after deployment.
- The account link needs `metric_collection_mode = "PUSH"`. The test AWS account already had an
  older API-polling (PULL) link and a separate metric stream that delivered to New Relic but
  produced no data in the sandbox beforehand; this is consistent with (but does not prove) stream
  data being dropped without a PUSH link.
- New Relic's AWS account id used in the trust policy (754728514883) and the external-id scheme
  were accepted by New Relic.

## Still unverified

  stopped and the Lambda functions idle, so they published no metrics during the test.
- Datadog: no live access (blocked on the corporate network).
- Percentile statistics, anomaly alarms and dashboards are not converted.
